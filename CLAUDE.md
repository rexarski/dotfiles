# Maintenance notes for this chezmoi source repo

This directory is the **source** for chezmoi; files render into `~/` via
`chezmoi apply`. Do not confuse source paths with target paths. Workflows
and commands live in [README.md](README.md) — this file is invariants only.

## Source ↔ target

| source name in this repo            | target path           |
| ----------------------------------- | --------------------- |
| `dot_X`                             | `~/.X`                |
| `private_X`                         | mode 0600             |
| `executable_X`                      | mode 0755             |
| `X.tmpl`                            | rendered Go template  |
| `private_Library/private_App.../X`  | `~/Library/App.../X`  |

`chezmoi add` picks prefixes automatically — never hand-name. Templates:
`chezmoi add --template`, or rename to `.tmpl` after.

## Editing flow (pick one direction)

- Source → target: edit here, then `chezmoi diff && chezmoi apply`.
- Target → source: `chezmoi re-add <target>`.
- Never edit both sides by hand. If `apply` prompts
  `diff/overwrite/.../quit`, the target is newer: **quit, then re-add**.
  `overwrite` discards the local edit.

## Secrets (this repo is PUBLIC)

- Never track `~/.config/gh/hosts.yml` — gh writes oauth tokens into it
  when keychain storage is unavailable. It was deliberately forgotten.
- `private_` controls file mode only; it does not encrypt or hide content
  from git. No API keys / tokens in any tracked file, ever.
- Before `chezmoi re-add` of any config an app rewrites,
  skim the diff for injected credentials.
- Secret-bearing configs need `chezmoi secret` / 1Password template
  lookups, not plain files.

## Skills

Skills are installed per machine and **not synced**: chezmoi does not
track `~/.agents/.skill-lock.json`. The repo keeps only `skills.txt`, a
plaintext `source<TAB>name` snapshot regenerated by `.githooks/pre-commit`
(`scripts/skills-manifest.sh`). Other machines install from it selectively.

- Every CLI skill enters via `skills add <owner>/<repo> -g -y [-s name]`;
  never hand-place dirs in `~/.agents/skills/`.
- App-owned real dirs coexist and must be left alone: `rex` (installed by
  the Rex terminal app, listed in skills.txt as `(app-installed)`), and
  `~/.claude/skills/synced/` (Claude's claude.ai account skill sync).
  Everything else in `~/.claude/skills/` is a CLI-managed symlink.
- A lock entry whose dir is missing makes `skills update` fail and the
  CLI cannot `remove` it; delete that entry from the JSON directly.
- `skills remove` wipes local copies; upstream packs rename/drop skills,
  so a removed skill may not be reinstallable. Confirm before removing.
- Never hand-edit `skills.txt`; the hook overwrites it each commit.
- Helper scripts live in `scripts/` here — repo-only, listed in
  `.chezmoiignore`, never rendered into `~/`.

## Linux / non-macOS

`.chezmoiignore` skips `Library/` and `.Brewfile` off darwin; the
install script renders empty (so it's skipped); gitconfig picks the
`op-ssh-sign` path per OS. New macOS-only files must join that ignore
block; new tools in fish config get an existence guard.

## Commit signing

`private_dot_gitconfig.tmpl` uses `{{ .chezmoi.homeDir }}` for the
signingkey/excludesfile paths so they render on any machine. Do **not**
hardcode `/Users/<name>/` in it. Signing chain: git → `op-ssh-sign` →
1Password agent. Pubkey + allowed_signers are tracked (public info);
the private key never leaves 1Password.

## Portability & churn

- Two Macs with different hostnames/usernames share this repo. Never
  branch on hostname; never hardcode `/Users/<name>/` (use `$HOME` in
  shell/fish, `{{ .chezmoi.homeDir }}` in templates). Machine-optional
  tools get an existence guard (`test -d …; and …`), not a per-host branch.
- Don't track configs apps rewrite themselves: zed settings,
  `~/.claude/settings.json` (Orca injects hooks), btop, gh config were
  deliberately forgotten. Don't re-add them. Same for opencode (Orca
  plugins), app `.plist`s, log-only dirs, and generated trees.
- Track only hand-written config: yazi is `package.toml` + `theme.toml`
  (plugins come back via `ya pkg install`); doom is its three `.el` files.
- A tracked config that a tracked script reads must travel with it
  (e.g. `fastfetch/greeting.jsonc` ↔ `fish_greeting.fish` ↔ `tips.txt`).
- `~/.gitignore_global` is the single global ignore (`core.excludesfile`
  makes `~/.config/git/ignore` dead); don't recreate the XDG one.

## Git hooks

`.githooks/` (repo-only, enable per clone with
`git config core.hooksPath .githooks`): `pre-commit` regenerates and
stages `skills.txt`; `commit-msg` rejects non-conventional messages.
Don't bypass with `--no-verify`.

## Keep the README in sync

README.md is the human reference. In the same commit: tracked-file
changes → update the tree; helper/flag changes → update workflows;
bootstrap changes (new dep, new init step) → update the bootstrap block.

## Don't

- Don't run `git` inside `~/` — only in this source dir (`chezmoi cd`).
- Don't commit without conventional-commit messages.
- Don't `rm` anything in `~/.claude/skills/` without confirming it's an
  orphan symlink (`rex` and `synced/` are app-owned real dirs — keep).
- Don't track high-churn or secret-prone files without a churn/secret
  guard (see above).
